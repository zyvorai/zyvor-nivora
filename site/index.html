Private by design

Local-first

No account, no cloud, no telemetry upload. The API listens on loopback with a random bearer token.

Observe-first

Rules default to observe. Block rules are one-hour leases and need the signed content filter to take effect.

No payloads

Flow metadata only. The one exception, packet capture, is off until you start it, headers-only, capped and deleted after 24 hours.

Get Nivora

Nivora is early. The native app and collector build and run today; the signed content filter and capture helper need an Apple Developer ID and entitlement.

Release builds are unsigned

The downloadable app is not signed or notarised, so macOS Gatekeeper blocks the first launch with “Nivora” cannot be opened because the developer cannot be verified. This is expected. You have three options:

  1. Build it yourself (below). A locally built app is never quarantined.
  2. Open Anyway. Try to open the app, then go to System Settings → Privacy & Security, scroll to Security and click Open Anyway. On macOS 14 you can instead Control-click the app and choose Open.
  3. Terminal: xattr -dr com.apple.quarantine /Applications/Nivora.app, only after checking the download against SHA256SUMS.txt.

Details and uninstall steps: docs/INSTALL.md.

# try it with simulated data, no install
python3 agent/nivora.py --demo

# monitor this Mac (dashboard + API on 127.0.0.1:9857)
python3 agent/nivora.py

# build the native app (needs Xcode and xcodegen)
brew install xcodegen
./scripts/build-native.sh
open native/build/Build/Products/Release/Nivora.app

FAQ

Does Nivora see inside my traffic?

No. It records which app talks to which endpoint, how much, and over which interface. Packet capture is a separate, opt-in feature that keeps only packet headers by default.

Does it block anything?

Not by default. Rules start in observe mode. Blocking needs the signed content-filter extension and your explicit rule, and expires after an hour unless made permanent.

Why does the demo show the same apps every time?

The hosted demo runs the real dashboard on simulated telemetry. A web page cannot read your processes, so the banner says so on screen.

What is tested and what is not?

The collector, API, dashboard and native app are built and tested with Python, Node and Xcode (unsigned). Signing, extension activation and the privileged capture helper have not been tested on a provisioned Mac; the docs say so.

macOS says Nivora can't be opened. Is it broken?

No. Release builds are unsigned and not notarised, so Gatekeeper blocks the first launch. Use System Settings → Privacy & Security → Open Anyway, or build the app yourself. See the install guide.

Which macOS versions?

macOS 14 or later. The app is SwiftUI with the Netra design language, shared with the browser dashboard.
